# 通用设置页 / 字体大小 / 深浅主题

> 适用版本：**v1.7.8（versionCode 20）** 起。
> 相关文件：`AppSettingsActivity.kt`、`BaseActivity.kt`、`util/UiPrefs.kt`、
> `res/layout/activity_app_settings.xml`、`res/values/attrs.xml`、`res/values/themes.xml`。

## 1. 为什么要单独建一个设置页

原来的入口只能算"不存在"：老人端首页是**横向分页**的，设置按钮在第 2 页最底部，
前面还隔着绑定码和后端连接；子女端根本没有 App 设置入口（只有"守护设置"）。
远程帮老人排查时永远要问"你现在装的是哪个版本"——因为版本号没有地方看。

现在的两端统一形态：

| 位置 | 形态 |
|---|---|
| 老人端首页 | 顶部一条常驻工具栏，右侧「⚙️ 设置」按钮（44dp 高），**三个分页都可见** |
| 子女端首页 | 同样在 fragment 容器上方加了工具栏 + 齿轮 |
| 设置页 | 版本与升级置顶 → 显示（字体/主题）→ 账号 → 更多 → 后端连接 |

## 2. 设置页里有什么

- **版本与升级**（第一屏最上面）：当前版本名 + versionCode + 「检查更新」按钮
- **显示**：字体大小（标准 / 大 / 超大）、界面风格（跟随系统 / 浅色 / 深色），下方有
  一行样本文字即时预览，选中项有绿色高亮标记
- **账号**：修改手机号与老人资料（仅老人端）、切换角色、退出登录
- **更多**：防护规则设置、守护健康自检（仅老人端）、电子围栏管理（仅子女端）
- **后端连接**：从老人端首页搬过来的连接地址输入与测试（仅老人端显示）

按角色隐藏而不是全部堆出来：子女端看到"电子围栏"，老人端看到"守护自检"，
互不干扰。

## 3. 字体大小是怎么全局生效的

不能在每个 Activity 里各写一遍——靠人记住"新建页面时加一段代码"迟早会漏。
收敛到基类：

```kotlin
// BaseActivity.kt
override fun attachBaseContext(newBase: Context) {
    super.attachBaseContext(UiPrefs.wrapContext(newBase))
}
```

`wrapContext` 把 `Configuration.fontScale` 覆盖成用户选的倍率（1.00 / 1.15 / 1.30）。
**是覆盖而不是叠加系统字体倍率**：很多老人已经在系统里调大了字体，再叠一层会到
1.5~1.8，卡片里的文字直接撑破布局（卡片高度是 dp 写死的，只有 sp 会被放大）。

切换后调用 `recreate()` 刷新。注意顺序：**先 Toast 再 recreate**，
拿已经作废的 Activity 上下文弹 Toast，部分机型会抛 `Activity has leaked window`。

> **新增 Activity 必须继承 `BaseActivity`**，否则该页面字体不跟随。
> 唯一的例外是 `EmergencyAlertActivity`（全屏警报页，有自己的 theme，
> 且弹出时用户不可能去调字体）。

## 4.1 切主题为什么必须重启进程（两个实测踩过的坑）

**坑 A：drawable 缓存不感知主题切换。**
带 `?attr/` 的 shape drawable（`bg_card_dark.xml` 里的 `?attr/appCard`）是在
Resources 级 drawable 缓存里解析主题色的。`recreate()` 只重建 Activity、
不清这个缓存，旧主题解析出的颜色被继续复用——实测表现：
"设置页全白了、首页那张总开关卡还是黑的"。所以切主题走
`restartApp()`（startActivity 启动意图 + `Runtime.exit(0)` 重启进程），
让所有资源按新主题重新解析。

**坑 B：重启前 `apply()` 会丢数据。**
`SharedPreferences.apply()` 是异步落盘，`exit(0)` 一退，没落盘的值就丢了——
实测表现："点了深色、重启回来还是浅色"。所以 `UiPrefs.setThemeMode`
用的是 `commit()`（同步落盘）。以后凡是"改完设置就重启进程"的写入，
都必须 `commit()`。

字体档位不受这两个坑影响（不涉及 drawable 主题色），保持 `recreate()`。

## 4. 深浅主题是怎么实现的

### 4.1 语义属性

`res/values/attrs.xml` 定义了 8 个语义属性，两套主题各给一套值：

| 属性 | 深色 | 浅色 | 含义 |
|---|---|---|---|
| `appBg` | #0F172A | #F1F5F9 | 页面底色 |
| `appCard` | #1E293B | #FFFFFF | 卡片/次级按钮底 |
| `appCardAlt` | #26314A | #F8FAFC | 更浅的卡片、分段按钮未选中态 |
| `appText` | #FFFFFF | #1E293B | 正文 |
| `appTextDim` | #94A3B8 | #64748B | 次要文字 |
| `appDivider` | #334155 | #E2E8F0 | 分割线 |
| `appInputBg` | #26314A | #FFFFFF | 输入框底 |
| `appInputText` | #FFFFFF | #1E293B | 输入文字 |

布局里写 `?attr/appText` 而不是具体色值，切换主题时一个字都不用改。

### 4.2 两个必须注意的顺序

```kotlin
// BaseActivity.onCreate
UiPrefs.applyNightMode(this)   // 同步 AppCompatDelegate
setTheme(UiPrefs.themeRes(this))  // 必须在 super.onCreate 之前
super.onCreate(savedInstanceState)
```

- `setTheme` 晚于 `super.onCreate` 会**静默失效**（不报错，就是不变）
- 只 `setTheme` 不同步 `AppCompatDelegate.setDefaultNightMode` 会出现
  "页面深色、弹窗白底"——Material 组件走的是 Delegate 的日夜判定

父主题分别是 `Theme.MaterialComponents.NoActionBar` 和 `.Light.NoActionBar`
（不是 DayNight），这样两套配色才真正独立。

### 4.3 代码里的颜色怎么取

`UiPrefs.color(context, R.attr.appText)`，另有 `textColor/dimColor/cardColor/bgColor`
四个快捷方法。

**判据**：表达**角色**的颜色（文字、次要文字、卡片、底色）必须走语义属性；
表达**状态**的红/黄/绿（诈骗风险等级、权限是否授予）两套主题通用，可以保持写死。
已经按这个标准改了 30 处（MainActivity、RiskLogActivity、EvidenceFragment、
GuideFragment、DashboardFragment、RecordingPlayerCard、TrackFragment、
MapPickerActivity、ElderGuardSettingsActivity）。

## 5. 发布

```bat
:: 1. android\app\build.gradle → versionCode +1、versionName 改
build-apk.bat
node scripts/publish-release.js --note "这次改了什么" --upload
```

> wrangler 上传必须真正 unset 代理：`env -u HTTP_PROXY -u HTTPS_PROXY -u http_proxy -u https_proxy`
> （写成 `HTTP_PROXY=` 空串 wrangler 仍然当代理用，会挂住）。
> 生产清单有 **5 分钟 KV 缓存**，发布/回滚后要等 5 分钟才生效。
