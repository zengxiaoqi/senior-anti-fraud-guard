P0体验缺陷：直接伤害使用的问题

这些问题在实际使用中会造成误操作、信息不可读或功能失效感，优先修复。

1危险操作与主操作视觉平权，且布局溢出P0
BEFORE · 现状问题「绑定」与「解除绑定」两个语义相反的按钮等宽并排；截图中「解除绑定」文字已被裁切（文字超出按钮）。「退出登录」红色高饱和常驻顶栏，紧邻「切换角色」，极易误触。
AFTER · 改版方案解绑降级为行内文字链接「解除」，点击后弹二次确认；退出登录移入设置页；切换角色改为底部低存在感的文字按钮。所有按钮触控区 ≥44dp，文字留足内边距。
2诊断术语与原始数据直出，守护人无法读懂P0
BEFORE · 现状问题「APP_CRASH（中危）」是内部事件枚举直接拼进文案；「28.2402, 113.0924」原始经纬度对普通人毫无意义；「位置更新（低危）」连续重复两条，无聚合、无时间、无价值。
AFTER · 改版方案服务端/客户端事件名映射为白话（APP_CRASH → 「老人端应用异常退出过 1 次，已自动恢复」）；位置走逆地理编码显示「常去地点②附近 + 相对时间」；同类事件聚合成「位置更新 ×2 · 时间区间」，详情进二级页。
3信息优先级倒置：没有"老人此刻状态"P1
BEFORE · 现状问题首屏被「我的手机号 + 大按钮」占据（低频配置）；守护人打开 App 最想确认的「老人安全吗、在哪、最近有没有事」需要滚动 + 自行拼接三张卡片才能得出。
AFTER · 改版方案新增 Hero 状态卡：老人昵称 + 在线状态点 + 「一切正常 / N 条需留意」状态徽章 + 最新位置（人类可读）与今日风险计数。打开即得到答案，点击可跳转亲情轨迹。
4绑定流程状态混乱：已绑定时仍显示绑定码输入P1
BEFORE · 现状问题已绑定「曾爷爷1」的状态下，输入框与「绑定」按钮仍然展示，用户会疑惑"再输一次会怎样"；状态行、输入框、双按钮挤在一起，三种状态（未绑/已绑/换绑）共用一套 UI。
AFTER · 改版方案按状态切换视图：未绑定 → 整卡引导输入绑定码（唯一主按钮）；已绑定 → 收起为一行「已绑定 · 曾爷爷」+「解除」链接；换绑入口放在解除确认后出现。名称「曾爷爷1」的序号后缀属于测试数据残留，也应清洗。
5手机号卡片权重过高、文案说教P1
BEFORE · 现状问题一张完整卡片 + 全宽蓝色主按钮只为"改手机号"这一个低频操作，且警示语常驻；真正需要警示的是"未填写"场景（ll_mobile_missing 黄条），已填写时反复施压反而造成焦虑。
AFTER · 改版方案降级为「账号与绑定」聚合卡中的一行：图标 + 标题 + 脱敏号码 132****0011 + 箭头。警示条件化：仅在未填写或号码疑似变更时显示黄色提醒条，填好后自动消失。
6视觉系统待统一：卡片无层次、按钮全是主色P2
BEFORE · 现状问题五张卡片同规格同底色堆叠，无视觉锚点；「配置围栏」「守护设置」「填写手机号」全为蓝底主按钮，主按钮失去"唯一主操作"的引导力；图标 emoji 与文字基线不齐。
AFTER · 改版方案建立三级层级：Hero 卡（渐变 + 18dp 圆角）→ 内容卡 → 聚合行；按钮分层 Primary（每屏最多 1 个）/ Tonal / Text；统一 14dp 圆角、12dp 卡距、8pt 间距栅格；图标改用带底色的容器（32dp，圆角 10dp）保证对齐。

落地路径（对应代码）

  1. 布局重排：fragment_family_dashboard.xml 按新稿重写 — Hero 卡置顶，手机号/绑定收进「账号与绑定」聚合卡，解绑按钮从布局移除改为行内链接。
  2. 文案人性化：DashboardFragment.kt 的 eventName() 补全映射（APP_CRASH 等），formatRecentEvents() 增加按 event_type 去重聚合；位置显示改用服务端已有的地名/常去地点字段，不再直出经纬度。
  3. 状态机：绑定卡按 boundElderId 三态渲染（未绑 / 已绑 / 换绑确认），参考既有 has() 三态约定。
  4. 条件警示：手机号黄条仅当 mobile 为空时 visibility = VISIBLE，已填写时隐藏常驻警示。
  5. 改完须双端验证：构建走 build-apk.bat，注意 bump versionCode；若动到服务端事件文案，routes/* 与 workers/src/routes/* 双写。
