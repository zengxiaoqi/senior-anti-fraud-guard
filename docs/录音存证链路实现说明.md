# 环境录音存证链路 · 实现说明

> 需求来源：老人端录音要能上报给子女收听、能作为报警证明材料、停止时机可控，
> 并在此基础上增加「录音转文字 + AI 诈骗研判」，**只有存在诈骗的才长期保留作为证据**。

---

## 一、为什么要这么设计

「只有诈骗的才保留」这条需求，字面实现是：`AI 判定为诈骗 → 永久保存；否则 → 立刻删除`。
**本实现没有照字面做**，原因是它有一个致命缺陷：

老人按 SOS 录音的那一刻，往往正是他已经在被骗过程中的那一刻。此时录音内容可能是
「喂您是客服吗？我那个养老钱……」，AI 因为文本短、口语化、没出现标准诈骗词库而判成 SAFE，
录音被立刻删掉——等子女几小时后看到告警想回听，证据已经没了。

所以实际策略是**分层保留 + 人工复核窗口**：

| 判定 | 保留策略 | 理由 |
|------|---------|------|
| `FRAUD` 诈骗 | **永久保留** | 已确证，直接作为证据 |
| `SUSPECT` 疑似 | 保留 14 天 | 有信号但不足以定性，留出人工判断时间 |
| `SAFE` 非诈骗 | 保留 14 天后自动清理 | 不是立刻删；到期前子女可人工推翻 |
| 转写失败/未配置 ASR | 保留 14 天，标 `SUSPECT` | **绝不能因为"分析不了"就当作"没问题"** |
| 子女人工复核过 | 永久保留 | 人工优先于 AI |

`RECORDING_SAFE_RETENTION_DAYS`（默认 14 天）是这条底线的时间刻度。

## 三、停止录音的四个时机

| 时机 | 触发方 | 实现 |
|------|--------|------|
| 满 N 段自动停 | 系统 | `GuardConfig.recordingMaxSegments`（默认 3 段 = 30 分钟，可 1~6 段） |
| 老人手动停 | 老人 | 主界面「⏹ 停止录音」按钮 + **通知栏「停止录音」按钮**（不用进 App） |
| 子女远程停 | 子女 | 证据页「远程停止」→ WS `RECORDING_STOP_CMD` → 老人端 `RECORDING_STOP` |
| 离开围栏 | 系统 | 仅 `GEOFENCE` 录音生效，不会打断 SOS 录音 |

**停止时正在录的那一段不会丢**——先 `releaseRecorder()` 再入队，这是 `stopRecording()` 里最容易写错的地方。

`recordingMaxSegments` 上限的意义：没有上限的话，老人按了 SOS 忘了这事，服务会一直录下去，
把手机存储和服务器磁盘同时撑爆；而且过长的录音反而更难被法庭采信。

## 四、接口清单

| 方法 | 路径 | 鉴权 | 说明 |
|------|------|------|------|
| POST | `/api/recordings/upload` | 开放（对齐 `/api/events/report`） | multipart 上传，sha256 幂等 |
| GET | `/api/recordings/list/:elderId` | Token + 绑定校验 | `?group=1` 按会话聚合，`?evidence=1` 只看证据 |
| GET | `/api/recordings/stream/:id` | URL 签名令牌 | 支持 Range，供播放器拖进度 |
| GET | `/api/recordings/pack/:elderId` | Token + 绑定校验 | zip 打包下载 |
| POST | `/api/recordings/:id/review` | Token + 绑定校验 | 人工复核（可推翻 AI 判定） |
| DELETE | `/api/recordings/:id` | Token + 绑定校验 | 删除记录与文件 |
| GET | `/api/recordings/status/:elderId` | Token + 绑定校验 | 老人端录音运行态 |

### 播放鉴权为什么用 URL 签名

`MediaPlayer` 播放 m4a 时**不会带自定义请求头**，所以收听录音没法走 `X-Auth-Token`。
解法是：已鉴权的 `list` 接口为每条录音签发 `base64url(payload).HMAC-SHA256`，
`payload = {rid, uid, exp}`，HMAC 覆盖整个 payload，30 分钟过期。

`verify(token, recordingId)` 真正做了三件事：验签（`timingSafeEqual` 防时序攻击）、
验过期、验 `rid` 与请求的录音一致——所以令牌**不可伪造、不可挪用给别的录音**。

## 五、WS 指令

| 方向 | type | 说明 |
|------|------|------|
| 老人 → 服务 | `RECORDING_STATE` | `STARTED` / `SEGMENT` / `STOPPED`，服务端维护 `elderRecordingState` |
| 子女 → 服务 → 老人 | `RECORDING_STOP_CMD` → `RECORDING_STOP` | 远程停止录音 |
| 服务 → 子女 | `RECORDING_UPLOADED` | 新录音到达 |
| 服务 → 子女 | `RECORDING_ANALYZED` | AI 研判出结论（含转写、标签、是否保留） |
| 服务 → 子女 | `RECORDING_STATE` | 同步「正在录音」指示灯 |

老人端掉线时 `elderRecordingState` 会一并清除，否则子女端会看到过期的"正在录音"红条。

## 七、诈骗研判规则

`services/fraudDetector.js` 纯本地、可离线、可复现，分两档：

**强信号（命中即高危）**——冒充公检法、涉案资金冻结、屏幕共享、安全账户、
索要验证码、保密要求、高额回报、荐股带单、虚拟币、注销校园贷、
冒充亲友急事借钱、恐吓威胁、限时施压…

**弱信号（累积加权）**——提及转账、银行卡、身份证件、陌生链接、投资项目、
要求保密、催促行动…

实测效果（`node -e` 直接跑 `analyzeByRules`）：

| 输入 | 判定 | 分数 |
|------|------|------|
| 公安局+涉嫌洗钱+资金冻结 | FRAUD | 98 |
| 屏幕共享+安全账户转账 | FRAUD | 100 |
| 王老师带单+年化30%稳赚 | FRAUD | 99 |
| 天气挺好的晚上吃饺子吗 | **SAFE** | **0** |
| 会销义诊+能根治不用吃药 | FRAUD | 68 |

家常对话零误报是这套规则能上线的前提——误报率高的规则会让所有录音都被长期保留，
等于没做筛选。

LLM 只在「规则判 SAFE 且文本 ≥40 字」时兜底复核，且 LLM 定性为诈骗但自身置信度 <70 时
**降级为 SUSPECT**，避免模型一次误判就把文件永久钉在服务器上。

## 八、报警材料的完整性

`routes/evidence.js` 里原来的 `checksum: HASH_${Date.now().toString(16)}` 是纯装饰——
每次导出都不一样，既不能复算也不能证明内容未被改动。现在改成真实的 SHA-256：

- **单文件级**：每段录音的 `sha256`（落盘时算，可现场复算比对）
- **证据包级**：对「守护对象身份 + 全部录音编号与文件摘要」再算一次 SHA-256

打包 zip 内含两份清单：
- `00_证据清单.txt` —— 给民警看的中文说明 + 逐条明细
- `01_证据清单.json` —— 结构化版，便于后续系统对接

## 九、法律合规提醒

代码注释里写清了，实现时也要注意：

1. **合法性前提**：仅在「老人主动按 SOS」或「进入子女事先登记的敏感地点」时录音。
   《个人信息保护法》第 13 条要求单独同意，非常态化、隐蔽式监听站不住脚。
2. **明示告知**：自动录音的开关应由子女端明确告知，并让老人首次确认，不要静默开录。
3. **第三方时间戳**：目前只有文件自身哈希，若要正式立案，建议再接
   法院认可的第三方时间戳服务（TSA）做可信时间证明。
4. **原始件保全**：不要在服务器上覆盖或转码原始录音，一切加工都另存副本。
