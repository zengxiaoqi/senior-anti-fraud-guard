# 技术方案

> 本文是「长者防诈守护」的完整产品设计与技术实现方案。面向开发者与评审者，解释**为什么这样设计**与**代码落在哪里**。
> 只想快速了解项目、看界面、跑起来，请看仓库根目录的 [README.md](../README.md)。

## 1. 背景与设计原则

### 1.1 核心痛点

1. **老人当局者迷**：老年人在遭受电信诈骗、保健品线下洗脑、养老投资骗局时，处于高度被洗脑状态，自身缺乏识别能力，不会主动触发求助或警报。
2. **传统监控侵权且不可行**：静默窃听、后台隐蔽录音、强行抓取微信/支付宝数据存在严重法律风险（违反《个人信息保护法》），且会被 iOS/Android 系统及安全软件直接封杀。
3. **事后维权举证难**：老人被骗后受限于记忆模糊、证据被抹除等原因，无法提供有效的收款账号、通讯记录与现场轨迹，导致警方难以立案和冻结资金。

### 1.2 产品核心设计原则

* **无感感知**：不依赖老人主动操作，通过行为特征分析自动识别异常。
* **合法合规**：基于透明授权 + 行为指标监测 + 系统公开 API，绝不进行隐蔽偷录或侵入式窃听。
* **实时干预**：构建「高危行为感知 → 子女端强提醒 → 远程亲情打断」闭环。
* **证据留存**：自动聚合资金流向链 + 通讯链 + 时空轨迹链 + 告知式场景录音，形成一键报案证据包。

## 2. 总体架构

系统由**一个双角色 Android App**（同一 APK 内切换老人端/子女端）、**子女端微信小程序**、**Node.js 后端**与 **Cloudflare Workers 边缘层**组成：

```
┌───────────────────────────────────────────────────────────────────────┐
│                           老人端（守护者角色）                          │
│  com.antifraud.guard · minSdk 26 · targetSdk 33 · arm64-v8a            │
├───────────────────────────────────────────────────────────────────────┤
│  行为感知          android/sensor/     跌倒检测（加速度）/ 通话状态监测   │
│  位置守护          android/location/   电子围栏 / 敏感地点停留 / 心跳上报 │
│  支付捕获          NotificationPayListenerService（通知栏监听）          │
│  AI 识诈           AiScanActivity      MLKit OCR + 云端 LLM 图文鉴定     │
│  场景存证          分段录音（5min/段）→ UploadQueue 上传                  │
└───────────────────────────────────────────────────────────────────────┘
         │ HTTPS / WSS（TLS，X-Auth-Token 鉴权）
         ▼
┌─────────────────────────────┐        ┌──────────────────────────────┐
│  本地后端 server.js          │        │  子女端                      │
│  Express + ws + SQLite       │◄──────►│  · Android App（同一 APK）    │

│  services/ 风险决策 研判     │        │  远程停录 / 一键证据包         │
└─────────────────────────────┘        └──────────────────────────────┘
         │ 同构镜像部署
         ▼
┌───────────────────────────────────────────────────────────────────────┐
│  生产环境：Cloudflare Workers（workers/，TypeScript）                    │
│  D1（SQLite 兼容）/ R2（APK 分发 + 录音对象）/ KV（发布清单缓存）          │
```

风险判定规则（是否打断、事件分级）在服务端、Android、小程序三处镜像，唯一真源见
`services/riskAlertPolicy.js` ↔ `family/RiskAlertPolicy.kt` ↔ 小程序 `app.js`。

## 3. 核心功能模块

### 3.1 异常行为无感感知（老人端）

| 模块 | 技术实现 | 判定逻辑 | 上报事件 |
| --- | --- | --- | --- |
| 通话行为监测 | `TelephonyManager` 通话状态 + 通讯录比对 | 陌生号码 / 单次 > 15 分钟 / 2 小时内同号 ≥ 3 次 | `EVENT_SUSPICIOUS_CALL` |
| 敏感地点停留 | 高德定位 + POI 分类 + 电子围栏（`android/location/`） | 离家状态在保健品店/养生讲座/银行 50m 内停留 > 40 分钟 | `EVENT_SENSITIVE_LOCATION_STAY` |
| 异常支付捕获 | `NotificationListenerService` 解析扣款/支付成功通知 | 单笔 > 500 元或 1 小时内连笔 | `EVENT_PAYMENT_DETECTED` |
| 跌倒检测 | 加速度传感器，失重前置连续多帧 ≥ 150ms + 撞击后抖动窗口验静止（`android/sensor/`） | 采样率 `SAMPLE_INTERVAL_MS` | `EVENT_FALL` |
| AI 图文识诈 | MLKit OCR + 云端多模态 LLM | 保健品宣传单/假收据/可疑短信截图 → 红黄绿评级 | AI 鉴定结果 |

细节：通话与跌倒阈值定义在服务端 `services/fraudDetector.js`；客户端只负责采信号，判定不采信客户端自报 severity。

### 3.2 亲情干预与强打断（子女端）

云端判定风险等级为高危（Red Alert）时：

1. **强提醒推送**：子女端收到高优先级音效推送（穿透静音），展示风险来源（如「母亲正与陌生号码通话 18 分钟」）。小程序走微信订阅消息，Android 走 WS + 通知。
2. **远程亲情强响/语音打断**：子女点击「远程拉起弹窗」，老人机屏幕覆红色安全提示，播放子女预录防骗语音，强制打断洗脑状态。
3. **资金风控联动**：大额支付存证同步至子女端，需远程确认后方可继续（远程停止录音同理）。

### 3.3 维权证据链聚合

不幸受骗时，子女端一键生成《反诈报案维权证据包》（ZIP，`services/zipWriter.js` + HMAC 签名下载）：

```
《反诈报案维权证据包》组成结构：
├── 1. 资金流向链
│   ├── 交易时间戳 / 扣款金额
│   ├── 收款方商户全称 / 商户号 / 银行卡号
│   └── 交易单据电子快照
├── 2. 通讯与话术链
│   ├── 诈骗电话号码 / 归属地 / 通话时长记录
│   └── 涉诈短信及诱导链接解析
├── 3. 空间轨迹链
│   ├── 老人停留地点 GPS 经纬度及地址
│   └── 现场停留起始时间与时长证明
└── 4. 场景合规存证
    └── 高危状态下经过界面公开告知录制的防诈环境音频片段
```

录音留存策略：FRAUD 级永久保留，SAFE/SUSPECT/转写失败保留 14 天人工复核（"分析不了"≠ 没问题，ASR 失败按 SUSPECT 处理）。

## 4. 法律合规与隐私安全保障

| 维度 | 合规要求 | 本方案落地方案 |
| :--- | :--- | :--- |
| **知情授权** | 严禁隐蔽偷窥 | 老人端首次安装时由子女与老人共同完成透明授权，主界面显著展示「防诈守护服务运行中」常驻通知。 |
| **音频录制** | 严禁后台窃听 | 不进行全局后台窃听。仅在系统判定高危状态时，界面明确弹窗告知「已开启亲情防诈安全存证」后方可录音。 |
| **数据传输** | 防止隐私泄露 | TLS 传输，`X-Auth-Token` 鉴权；敏感支付信息与轨迹仅对绑定亲情账号可见（`requireBoundElder` 强制绑定校验）。 |
| **应用市场** | 符合国内厂商规范 | 不使用隐藏图标、注入漏洞等木马手段，无障碍服务仅用于「跳过开屏广告」白名单匹配，点击目标面积与祖先深度均有上限。 |

隐私红线：`data.sqlite`、录音 `uploads/`、keystore、`.env` 均不进版本库；录音按扩展名单独拦截，误入 git 历史即视为泄露。

## 5. 技术栈

| 层 | 选型 | 说明 |
| --- | --- | --- |
| 老人/子女端 App | Android Native（Kotlin / Jetpack，单 APK 双角色） | 深度调用后台定位、通知栏监听、无障碍服务 |
| 子女端小程序 | 微信原生小程序 | 免安装，扫码即用 |
| 后端（本地） | Node.js + Express + SQLite + ws（CommonJS，零构建） | `npm start` 直接跑 |
| 后端（生产） | Cloudflare Workers + D1 + R2 + KV + Cron | `workers/` 与本地同构镜像，双写维护 |
| AI 能力 | MLKit OCR（端侧）+ 多模态 LLM（ASR 转写 / 诈骗研判，可插拔 Provider） | 缺配置自动降级不崩 |
| Web 面板 | `public/index.html` 静态管理页 | 演示/排障 |

## 6. 结论

通过「合规行为感知 + 子女远程干预 + 自动化证据链」三位一体的闭环设计，既满足法律合规与上线要求，又能真正为老年人构建起一道坚不可摧的防诈安全屏障。工程上的取舍（三端镜像规则、缺配置降级、误报比漏报更危险的风控取向）详见 [AGENT.MD](../AGENT.MD) 铁律与 [docs/](.) 下各专题文档。
